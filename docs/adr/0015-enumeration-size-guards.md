# Size guards on enumeration

Functions that build lists throw above a size limit, so a typo such as `/8` for `/28` fails fast instead of exhausting evaluation memory. `cidr.hosts` and `ipRange.addresses` stop at 2¹⁶ entries; `portRange.ports` and `ipBindpoint.endpoints` stop at 4096. Each has an `*Unbounded` sibling, and indexed access (`cidr.addressAt`, `portRange.portAt`, `ipRange.addressAt`, `ipBindpoint.endpointAt`) reaches into large ranges without listing them. Indexed access does not need a large range's size: a non-negative index counts up from the start and a negative one back from the end, so only a range below 2⁶³ addresses, whose size a Nix integer holds, can put an index out of range. On a larger one, such as an IPv6 `/64`, every `Int` index lands inside, so `cidr.addressAt 1` reaches its gateway.

`cidr.subnets` caps its split depth at 16, or 2¹⁶ blocks, and has no unbounded sibling: its argument states the block count directly, rather than deriving it from a prefix where one mistyped digit multiplies the size.
